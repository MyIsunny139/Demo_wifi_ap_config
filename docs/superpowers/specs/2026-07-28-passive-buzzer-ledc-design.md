# GPIO14 无源蜂鸣器 LEDC 声光报警设计

## 目标

在现有 ESP32-S3 视频人员检测固件中增加一个三线 MH-FMD 无源蜂鸣器。模块使用 5V 供电，由 GPIO14 输出 PWM 音频信号，与 GPIO48 上的 WS2812 共同反映 `low`、`medium` 和 `high` 三档风险。

实测在 5V 供电时，将模块输入端接地只会短响一次或无持续声音。这与无源蜂鸣器需要交流方波驱动的行为一致，因此不再采用持续低电平触发方案。

## GPIO 选择

摄像头已经占用 GPIO4-13 和 GPIO15-18，WS2812 占用 GPIO48。GPIO19/20 用于 USB，GPIO43/44 用于 UART0，GPIO26-37 由 N16R8 模组的 Flash 和 Octal PSRAM 使用或保留，GPIO0、3、45、46 是启动绑带脚。GPIO14 未被当前固件占用，也不属于上述受限引脚，因此作为蜂鸣器 PWM 输出脚。

## 软件结构

蜂鸣器逻辑并入现有 `status_led` 组件，不创建第二个任务或风险队列。`status_led_task` 继续作为声光状态的唯一所有者：收到风险命令后同时更新 LED 和蜂鸣器，超时或清除风险时同时关闭两者。对外 API 保持不变，`video_stream` 无需知道蜂鸣器细节。

GPIO14 使用 ESP-IDF LEDC 外设产生 2 kHz、50% 占空比的 PWM。LEDC 定时器和通道只在 `status_led_init` 中初始化一次；发声阶段设置占空比，静音阶段停止输出并将 GPIO14 保持为低电平。初始化失败时返回错误，不启动状态任务。

## 报警行为

| 状态 | WS2812 | 蜂鸣器 |
| --- | --- | --- |
| 启动自检 | 绿色亮 300 ms | 2 kHz 响 100 ms |
| 低风险 | 熄灭 | 静音 |
| 中风险 | 琥珀色慢闪 | 2 kHz 响 500 ms、停 500 ms |
| 高风险 | 红色快闪 | 2 kHz 响 150 ms、停 150 ms |
| 5 秒无有效风险指令 | 熄灭 | 立即静音 |

蜂鸣器和 LED 使用同一个 `on` 相位，使每档风险的声光节奏同步。重复收到相同风险指令会刷新 5 秒超时并从亮灯、发声相位重新开始。

## 硬件连接与安全

- MH-FMD `VCC` 接 5V。
- MH-FMD `GND` 与 ESP32-S3 共地。
- MH-FMD `IO` 或 `IN` 接 GPIO14。
- GPIO14 只输出 0V/3.3V PWM，不得连接到 5V。
- 上电前测量模块输入端对地电压；如果模块会把输入端内部上拉到 5V，必须增加三极管、MOS 管或电平转换，不能直接连接 ESP32 GPIO。

## 修改范围

- 修改 `components/status_led/status_led.c`：初始化 LEDC、增加 PWM 启停函数，并接入自检、风险闪烁、超时和清除路径。
- 修改 `components/status_led/CMakeLists.txt`：声明 LEDC 所需的驱动依赖。
- 修改 `README.md`：记录 GPIO14 接线、2 kHz PWM 和三档声光行为。
- 不修改 `video_stream` 的风险协议和 Python 服务。

## 错误处理

- LEDC 定时器或通道初始化失败时，记录错误并让 `status_led_init` 返回失败。
- WS2812 初始化、队列创建或任务创建失败时，确保 PWM 已停止。
- 低风险、风险超时及 `status_led_clear` 最终都通过同一输出函数关闭蜂鸣器，避免遗漏静音路径。

## 验证

先执行源码级测试或静态检查，验证风险状态到 LED/PWM 输出的映射、GPIO14 无重复占用、所有关闭路径都会停止 PWM，并检查 CMake 依赖和空白错误。按照项目约定，本次不执行 ESP-IDF 编译。最终硬件测试依次确认启动自检、中风险慢响、高风险快响、低风险静音和 5 秒超时静音。
