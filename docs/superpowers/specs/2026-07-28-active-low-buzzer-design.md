# GPIO14 低电平蜂鸣器声光报警设计

## 目标

在现有 ESP32-S3 视频人员检测固件中增加一个三线有源蜂鸣器。蜂鸣器使用 GPIO14，低电平触发，与 GPIO48 上的 WS2812 共同反映 `low`、`medium` 和 `high` 三档风险。

## GPIO 选择

摄像头已经占用 GPIO4-13 和 GPIO15-18，WS2812 占用 GPIO48。GPIO19/20 用于 USB，GPIO43/44 用于 UART0，GPIO26-37 由 N16R8 模组的 Flash 和 Octal PSRAM 使用或保留，GPIO0、3、45、46 是启动绑带脚。GPIO14 未被当前固件占用，也不属于上述受限引脚，因此作为蜂鸣器控制脚。

## 软件结构

蜂鸣器逻辑并入现有 `status_led` 组件，不创建第二个任务或风险队列。`status_led_task` 继续作为声光状态的唯一所有者：收到风险命令后同时更新 LED 和蜂鸣器，超时或清除风险时同时关闭两者。对外 API 保持不变，`video_stream` 无需知道蜂鸣器细节。

## 报警行为

| 状态 | WS2812 | 蜂鸣器 |
| --- | --- | --- |
| 启动自检 | 绿色亮 300 ms | 低电平响 100 ms |
| 低风险 | 熄灭 | GPIO14 高电平，静音 |
| 中风险 | 琥珀色慢闪 | 500 ms 响、500 ms 停 |
| 高风险 | 红色快闪 | 150 ms 响、150 ms 停 |
| 5 秒无有效风险指令 | 熄灭 | 立即静音 |

蜂鸣器和 LED 使用同一个 `on` 相位，因此每档风险的声光节奏保持同步。初始化时先把 GPIO14 配置为输出并置高，降低启动误响概率；初始化失败或组件清理时也保持高电平。

## 硬件连接

- 蜂鸣器模块 `IN` 接 GPIO14。
- 蜂鸣器模块 `GND` 与 ESP32 共地。
- `VCC` 按模块额定电压连接。
- 建议在 `IN` 和 3.3V 之间增加 10 kΩ 上拉，避免复位阶段悬空误响。
- 如果 5V 供电模块会把 `IN` 内部上拉到 5V，必须增加三极管、MOS 管或电平转换，不能让 ESP32 GPIO 承受 5V。

## 修改范围

- 修改 `components/status_led/status_led.c`：配置 GPIO14、增加蜂鸣器开关函数，并将其接入自检、风险闪烁、超时和清除路径。
- 修改 `components/status_led/CMakeLists.txt`：声明 GPIO 驱动依赖。
- 修改 `README.md`：记录 GPIO14 和三档声光行为。

## 验证

执行源码静态检查，确认 GPIO14 没有重复占用，所有关闭路径都将蜂鸣器置高，并检查 CMake 依赖和空白错误。按照项目约定，本次不执行 ESP-IDF 编译；最终由硬件测试确认低电平触发、电平兼容性和实际音量。
